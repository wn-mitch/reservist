# Speaking and commitment

**ID:** `design.interface.speaking-and-commitment`
**Status:** `canonical`
**Depends on:** `design.interface.folders-and-handoff`, `design.information.claims-publication-and-audiences`

Conversation normally participates in a working folder and commits with its handoff. One explicit exception applies to an authored inquiry, question, disclosure, or statement marked `commits on speaking`. Selecting it passes the turn to the counterpart and immediately submits the bound typed communication act or request.

A commits-on-speaking option cannot be penciled, executed secretly for preview, or undone by closing the containing folder. Its practical card is visible before selection and states the speaker, audience, claims or question, authority, confidentiality, disclosures, capacity cost, timing, and explicit non-effects. Runtime admission and any later answer, delivery, publication, or reaction remain separately witnessed stages.

Godot sends only the selected authored option ID. Rust resolves the bound claims, command, eligibility, and current context, then returns an accepted or rejected receipt and refreshed player-safe projection. Rejection leaves canonical state unchanged and explains the available institutional reason without exposing hidden facts.

Ordinary dialogue navigation remains non-effectful. The interface marks commitment timing clearly so the player can distinguish rehearsal, a penciled folder choice, and speech that itself becomes institutional history.
